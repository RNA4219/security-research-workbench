# 継続回帰テスト計画

基準: 要件定義 FR-01〜15、2026-10-04 manual-bb 12ケース、RanD実文書監査、Code-to-gate解析。
従来の手動確認だけで終わらせず、失敗時の永続データ・原本・入力保持まで自動回帰する。

|優先度|観点・技法|判定基準|実行層|
|---|---|---|---|
|P0|保存の状態遷移・競合・例外ロールバック|古いrevision/不正参照で部分更新しない。履歴と原本を保持|API/SQLite/ブラウザー|
|P0|根拠の決定表|known/unknown/empty × 検証状態 × 資料版。根拠不足は承認・契約へ進めない|domain/ブラウザー|
|P0|通信失敗→手動再試行|フォーム入力を保持し、自動再送せず、復帰後に1件保存|ブラウザー|
|P1|取込の同値分割・境界|空/正当/不正JSON、文字数上限±1、ファイル上限。失敗原本を保持|schema/API/ブラウザー|
|P1|承認後変更の状態遷移|source/evidence/claim/前提/要件の変更に応じて承認失効、再確認可能|domain/ブラウザー|
|P1|memx連携の障害・再試行|HTTP異常、JSON異常、応答サイズ、部分成功から再試行、コア不変|実ループバックHTTP/API|
|P1|任意アダプター|成功・不在・API不適合・不正グラフでコア契約を維持|unit/optional smoke|
|P1|画面の全作業入口|設定、根拠作成編集、各出力、履歴、戻す、閉じる、モバイル|ブラウザー|

`npm run test:quality` が単体/APIと実ブラウザーの計測を統合する。全srcを分母に残し、全体の行・文・関数・分岐90%、ファイル別の行90%・分岐85%、v0.1からの変更行90%を最低条件にする。製品ビルドには計測コードを入れない。スタブ依存テストは実サービス相互運用の代替とは扱わない。manual-bbの実操作証跡と自動E2Eは区別する。
