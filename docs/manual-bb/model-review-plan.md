## Gate

機能ゲートはP0/P1全件成功、既存のカバレッジ閾値維持、重大欠陥0を必要とする。モデル比較は実行前manifestのpreflightと実行後の出力・ハッシュ検査を必要とする。単体試験の件数だけで通過させない。

効果ゲートでは、固定した評価集合に対してBの見逃し・誤検知がAを上回らず、少なくとも一方が減ることを確認する。Cでは見逃し・誤検知を増やさず、同条件の既知事項を人に再提示する件数が減ることを確認する。前提変更の負の対照では古い判断により新たな問題が隠れないことを必要とする。開発用だけの改善では通過させず、未使用の評価用集合でも判定する。計測失敗は効果ゼロとして埋めない。

## Go/No-Go brief

判定: **no_go（実モデルの効果未実証）**。修正後の全体検査03では、単体・統合336件、ローカル画面51件、公開サンプル6件が成功し、自動品質ゲートを通過した。全体の分岐カバレッジは90.02%、診断サービスは85.31%で、既存の基準を維持している。実モデル比較01〜03は失敗または効果不合格で、04は実行中。確認待ち評価04では同条件1例だけの除外と14例の再確認に成功したが、これを診断精度や人の時間短縮の証拠にはしない。証跡は[検証記録](../testing/2026-10-05-model-review.md)からたどれる。

合成コードの限定評価・登録製品の検証・実利用者の所要時間・Logosとの比較を混同しない。評価集合で改善しなければ機能提供と効果主張の判定を分け、要求全体は未完了として残す。
