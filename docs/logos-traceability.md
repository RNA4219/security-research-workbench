# Logos記事と要求・要件の対応

2026-10-05。正本は[要求・要件定義 v5](requirements.md)。この文書は記事の要点、本製品での適用、実装と試験の対応を記録する。v3実装前の基準は `627efd5`、その検証は[実行記録](testing/2026-10-04-logos-workflow.md)を参照。記事の技術選定や数値を、そのまま本製品の必須条件にはしない。

**v5で追加する受入:** 保存・管理の実装だけでは、記事の「知識を使うことで診断が改善する」という効果を満たさない。FR-38〜42で実モデルの静的レビュー、現行知識と過去判断の接続、同条件比較を必須にした。[受入計画](manual-bb/model-review-plan.md)の機能ゲートと効果ゲートを分けて判定する。現在は実装・評価中であり、Logosと同等以上の診断能力を実証した状態ではない。

**v4での訂正:** 本来の目的は特定製品の継続的な脆弱性診断である。下表の管理機能だけでは、製品コードの診断と変更後の再評価を満たさない。UR-00 / FR-32〜37に固定コミットの実解析と比較の実装・試験を追加した。以下のv3既存試験を、新しい中核機能の合格証跡として流用しない。

## 一次資料

- SRC-H: [Horos・ハーネス編](https://blog.cybozu.io/entry/logos-harness-horos)。工程を継続できる土台と、結果・判断を次の仕事に生かす仕組みを要求の根拠とする。
- SRC-E: [Ergon・LLM-Wiki編](https://blog.cybozu.io/entry/logos-llm-wiki-ergon)。目的に即した製品知識と、利用結果による知識の更新を要求の根拠とする。
- SRC-R: [まとめ編](https://blog.cybozu.io/entry/logos-retrospective)。モデルの交換、蓄積した判断基準の活用、運用と修正への接続を要求の根拠とする。

以下のID・状態・受入条件は本製品向けの設計判断。Horos・Ergonの配布実装を取得・統合済みという意味ではない。

## v2からの訂正と優先関係

提供されたDeep Research本文はLogos/Ergonの考え方を採用する一方、実行ループを対象外とした。v2も資料・比較・要件への変換に範囲を絞った。その結果、知識と判断を使って継続的に仕事を進める要求が、受入条件まで落ちていなかった。

v3で管理機能を追加した後も、製品コードを実際に診断する中核が欠落していた。利用者の指摘によりv4で目的と不足要件を訂正し、v5で製品知識を使う実モデルレビューと効果の比較評価を必須にした。判断の優先順は、最新の利用者要求→本要件定義v5→機能別仕様→過去の調査・検証記録とする。古い検証のGo判定やテスト件数は、当時の範囲に限る。

公開版は継続診断のモックと、実データを使う補助のOSS採用調査を案内する。SQLite保存とサーバー側のモデル接続が必要な継続診断はローカル版で扱う。静的な公開サイトへ案件データや秘密鍵を配置しない。
