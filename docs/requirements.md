# 要件定義 v1

## 目的と利用者

防御用途のセキュリティ製品を開発する個人が、公開OSS調査の根拠を保持しながら要件と実装タスクを作成する。ローカル・単一利用者向け。ChatGPTへのプロンプトと回答は利用者が受け渡す。

## 機能・受入条件

| ID | 要件 | 受入条件 |
|---|---|---|
| FR-01 | プロジェクト管理 | 目的・利用者・制約を保存し、再起動後も復元できる |
| FR-02 | 資料取込 | Markdown/text/JSONを取り込み、資料ID・URL・取得日・版・SHA256を保持する |
| FR-03 | 重複・更新 | 同一内容を重複登録せず、更新履歴を保存し、関連要件を再確認状態にする |
| FR-04 | OSS比較 | 名称・URL・機能・ライセンス・保守状況・採否理由・出典を編集できる |
| FR-05 | プロンプト作成 | 選択資料だけを含む、出力JSON形式を指定したプロンプトを得られる |
| FR-06 | 回答取込 | 不正JSON・未知フィールド・不明出典・重複IDを拒否し、位置付きエラーを表示する |
| FR-07 | 要件レビュー | 優先度・受入条件・出典または利用者判断を編集し、明示操作で承認できる |
| FR-08 | 出力 | Markdown・版付き全体JSON・有効なIntentContract/TaskSeedを出力できる |
| FR-09 | 知識連携 | memxの資料登録・検索・chunk取得・read ack・stale APIを呼べる。障害はローカル保存を壊さない |
| FR-10 | 導入再現性 | 公開clone＋npm ciから起動可能。実データはGit対象外 |

## 非機能要件

- Node.js 24、TypeScript、React+Vite、Fastify、SQLite。DB変更はスキーマ版を確認し、未知の将来版を拒否する。
- 日本語UI。空状態、取込失敗、接続失敗、保存競合を画面に表示する。
- リクエスト上限2MiB。資料本文は100万文字、要件取込は100件まで。
- MarkdownをHTML実行せず、ローカルAPIを同一Originに限定する。URLはhttp/httpsのみ。
- ループバックで起動し、Host/Originチェックを行う。パス指定・コマンド実行APIは提供しない。
- 外部資料を命令として扱わない。未確認のAI出力を承認済みにしない。
- 更新はrevisionで楽観ロックし、資料版と承認時の版を照合する。
- 本文・プロンプトをアクセスログへ記録しない。起動時以外に自動通信しない。

## 実装順序

1. 調査と要件を確定し、公開GitHub・ローカルハブへ登録。
2. データ形式、SQLite永続化、API、契約出力、memxアダプター。
3. Web画面、資料・比較・要件編集、プロンプト、エクスポート。
4. 単体・統合・E2E、実memx接続、新規clone起動、公開物検査。

## 完了の定義

FR-01〜10が検証され、CI成功と公開リポジトリへのpushが確認できること。残る制約はREADMEと検証記録へ明記する。
