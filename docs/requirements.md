# 要件定義 v2

2026-10-04更新。利用者が提供したDeep Research本文「security-research-workbench 公開情報調査・要件定義案」を照合し、v0.1で不足していた根拠モデル・比較レビュー・独立契約を追加した。

## 目的と利用者

OSSの採用を検討する個人が、公開リポジトリURLから保守情報と依存関係の既知問題を取得し、採用前の確認事項を得る。ローカル・単一利用者向け。入口の自動調査は[RR-01〜07](repository-research.md)を満たす。既存の手動調査・比較・要件化も利用でき、そのChatGPTへのプロンプトと回答は利用者が受け渡す。

## 機能・受入条件

| ID | 要件 | 受入条件 |
|---|---|---|
| FR-01 | プロジェクト管理 | 目的・利用者・制約を保存し、再起動後も復元できる |
| FR-02 | 資料取込 | Markdown/text/JSONを取り込み、資料ID・URL・取得日・版・SHA256を保持する |
| FR-03 | 重複・更新 | 同一内容を重複登録せず、更新履歴を保存し、関連要件を再確認状態にする |
| FR-04 | OSS比較 | 名称・URL・機能・ライセンス・保守状況・採否理由・出典を編集できる |
| FR-05 | プロンプト作成 | 選択資料だけを含む、出力JSON形式を指定したプロンプトを得られる |
| FR-06 | 回答取込 | 不正JSON・未知フィールド・不明出典・重複IDを拒否し、位置付きエラーを表示する |
| FR-07 | 要件レビュー | 優先度・受入条件・出典または利用者判断を編集し、明示操作で承認できる |
| FR-08 | 出力 | Markdown・版付き全体JSON・独立したWorkbenchTaskContractを出力できる。任意アダプターでIntentContract/TaskSeedへ変換できる |
| FR-09 | 知識連携 | memxの資料登録・検索・chunk取得・read ack・stale APIを呼べる。障害はローカル保存を壊さない |
| FR-10 | 導入再現性 | 公開clone＋npm ciから起動可能。実データはGit対象外 |
| FR-11 | 根拠グラフ | 要件→Claim→複数Evidence→資料URLをUI・Markdown・契約で追跡でき、Evidenceから関連要件も確認できる |
| FR-12 | 項目単位の比較 | カテゴリ・用途・機能・ライセンス・リリース・コミット・archive・Issue/PR・統合方式・入出力・運用・保守を比較する。known/unknown/emptyを区別し、各主張に確認状態とEvidence参照を持つ |
| FR-13 | 比較承認ゲート | 確認済みの根拠を持つ既知の値、明示的な未確認・値なしを人がレビューする。承認済み比較だけをプロンプトへ含め、必要なEvidenceの資料が欠落すれば拒否する |
| FR-14 | 任意依存と契約 | objective/scope/outOfScope/requirements/acceptanceCriteria/sourceRefsと根拠グラフをversioned schemaで出力する。両アダプター未導入でCoreが動作し、連携失敗でも保存状態が変わらない |
| FR-15 | 判断履歴と移行 | draft/approved/needs_review/needs_evidence/needs_revision/rejectedと理由・日時・revisionを保持する。資料・根拠・主張・前提の変更で関連承認を失効させ、v1 DBの既存履歴と原文を保持して移行する |
| FR-16 | 公開脆弱性知識 | 利用者がCVE IDを指定してOSV・CISA KEV・FIRST EPSSを明示照会できる。掲載・OSV撤回・未掲載・取得失敗を区別し、出典・照会時刻・応答ハッシュを示す。OSV範囲イベントを意味を変えず保持し、掲載のある提供元ごとに未検証の資料としてのみ保存できる |

## 非機能要件

- Node.js 24、TypeScript、React+Vite、Fastify、SQLite。DB変更はスキーマ版を確認し、未知の将来版を拒否する。
- 日本語UI。空状態、取込失敗、接続失敗、保存競合を画面に表示する。
- リクエスト上限2MiB。資料本文は100万文字、要件取込は100件まで。
- MarkdownをHTML実行せず、ローカルAPIを同一Originに限定する。URLはhttp/httpsのみ。
- ループバックで起動し、Host/Originチェックを行う。パス指定・コマンド実行APIは提供しない。
- 外部資料を命令として扱わない。未確認のAI出力を承認済みにしない。
- 更新はrevisionで楽観ロックし、資料版と承認時の版を照合する。
- 本文・プロンプトをアクセスログへ記録しない。利用者がリポジトリ調査・CVE照会・memx操作を実行した時だけ外部通信する。リポジトリ調査は認証なしの固定GitHub APIとOSV APIに限定し、OSVには公開lockfileの依存名・版だけを送信する。CVE照会ではCVE IDのみを送信する。

## 実装順序

1. 調査と要件を確定し、公開GitHub・ローカルハブへ登録。
2. データ形式、SQLite永続化、API、契約出力、memxアダプター。
3. Web画面、資料・比較・要件編集、プロンプト、エクスポート。
4. 単体・統合・E2E、実memx接続、新規clone起動、公開物検査。
