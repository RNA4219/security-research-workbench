# Security Research Workbench

まずは **[サンプル画面を開く](https://rna4219.com/open/security-research-workbench/)** と、使い方を確認できます。インストールは不要です。

**同じ製品を更新のたびに診断し、脆弱性の指摘から修正確認までを記録するローカルアプリです。**

公開サンプルは架空データを使ったモックです。実際に製品を診断するには、ローカル版を起動してください。

## 何に使う？

製品の更新後に、次のことを確認するために使います。

- 新しく見つかった問題はあるか。
- 前回の問題は、まだ残っているか。
- 修正後のコードとテスト結果を、人が確認したか。

例えば、外部通信の設定に問題が見つかったら、指摘と担当者の判断を記録します。修正版をもう一度診断し、前回からの変化を確認できます。

**指摘が消えただけでは、修正完了にしません。** 担当者が修正内容とテスト結果を確認してから、対応を完了にします。調査で分かった製品の仕様や注意点も、承認したうえで次回に引き継げます。

毎回ゼロから調べ直さずに、前回の指摘・判断・修正の記録を使って確認を続けるためのアプリです。

## 公開サンプルとローカル版の違い

| 使い方                                                                | できること                                                   | データ                                              |
| --------------------------------------------------------------------- | ------------------------------------------------------------ | --------------------------------------------------- |
| [公開サンプル](https://rna4219.com/open/security-research-workbench/) | 診断から修正確認までの4場面を見る                            | 架空データ。実際の診断・保存・定期実行はしません    |
| ローカル版                                                            | 登録した製品を診断し、前回と比較する。判断や修正の記録を残す | 自分のPCに保存します                                |
| OSS採用前調査（補助機能）                                             | 公開GitHub URLから、保守状況・依存関係・既知の問題を調べる   | GitHubとOSVの実データ。公開版とローカル版で使えます |

公開サンプルでは、**初回診断 → 更新後の比較 → 修正後の再評価 → 人の確認・知識承認**を切り替えて見られます。[公開ツール一覧](https://rna4219.com/open/)からも開けます。

## ローカル版を起動する

必要なものは **Node.js 24とGit** です。

初めて使う場合は、ターミナルで次を実行してください。

```sh
git clone https://github.com/RNA4219/security-research-workbench.git
cd security-research-workbench
npm ci
npm run build
npm start
```

起動後は、次の順に操作します。

1. [ローカル画面](http://127.0.0.1:4317)を開く。
2. 製品名、診断するリポジトリ、対象のブランチまたはコミット、製品仕様を登録する。自分の製品を選べない場合は、先に[対象リポジトリを設定する](docs/product-diagnostics.md#対象リポジトリを設定する)。
3. 診断を開始し、指摘されたコードの場所と、診断できなかった範囲を確認する。
4. 製品仕様と照らし合わせて、指摘の影響と対応方針を判断する。
5. 修正版を再診断し、通常の動作テストの結果も確認してから、修正完了を判断する。

診断対象は、開始時に確定したコミットです。未コミットの変更は含みません。定期実行は初期状態では無効で、製品ごとに設定できます。実行するには、ローカル版のサーバーを起動しておく必要があります。

記録はリポジトリ内の `.data/` に保存します。Gitには含めません。詳しい操作は[製品の継続診断ガイド](docs/product-diagnostics.md)を参照してください。

<details>
<summary>Windowsで、ターミナルを閉じても使い続ける</summary>

ビルド後、`npm start`の代わりにPowerShellで次を実行します。

```powershell
./scripts/local-server.ps1 start
```

状態の確認と停止には、それぞれ次のコマンドを使います。

```powershell
./scripts/local-server.ps1 status
./scripts/local-server.ps1 stop
```

PCを再起動した後は、再び `start` を実行してください。接続できないときは `status` で起動状態を確認します。

使用するポートは4317、データベースは `.data/workbench.db` です。ログとプロセス情報は `.cache/runtime/` に保存します。`stop` は、起動時のプロセス情報と一致するサーバーだけを停止します。

</details>

## 現在の診断範囲

| 対象                            | 確認する内容                                                               |
| ------------------------------- | -------------------------------------------------------------------------- |
| JavaScript / TypeScriptのコード | 証明書の検証や暗号に関する、一部の設定・呼び出し                           |
| npmの依存関係                   | lockfile v2/3に記録されたパッケージ名・版と、OSVの既知の脆弱性情報との照合 |

未対応の言語、解析に失敗したファイル、情報を取得できなかった範囲は、**未診断・未確認**として残します。

OSVへの照会は、製品設定で許可した場合だけ行います。送るのは依存パッケージの名前と版で、この照会でコードや製品仕様を送ることはありません。

**未知の脆弱性を広く発見する性能や、AIモデルの診断精度は、まだ実証していません。** 診断ルールと制限は[診断の範囲](docs/product-diagnostics.md#診断の範囲)を参照してください。

## 補助機能：使いたいOSSを調べる

OSSを導入する前に、更新履歴・ライセンス・依存関係を確認する機能です。ChatGPTへの貼り付けやAPIキーは不要です。

1. 公開版の下部にある「OSS採用前調査（実データ・補助機能）」を開く。ローカル版では「OSS採用前調査（補助）」を開く。
2. 公開GitHubリポジトリのURLを入力し、「このOSSを調べる」を押す。
3. 確認事項と出典を読む。必要なら結果をMarkdownでダウンロードする。

試すURLには、このリポジトリを使えます。

```text
https://github.com/RNA4219/security-research-workbench
```

結果には、確認日時と対象コミットも残ります。例えば、依存パッケージに既知の問題があれば、パッケージ名・版・lockfile内の場所・公開情報に記載された修正版を表示します。リポジトリがアーカイブされていたり、ライセンスを確認できなかったりした場合も、確認事項として表示します。

**この補助機能は、製品コードの診断は行いません。** 取得できなかった情報は未確認として残します。

<details>
<summary>調査範囲・保存先・通信の制限</summary>

- 保守情報は言語を問わず調べます。依存関係は、リポジトリ直下の `npm-shrinkwrap.json` / `package-lock.json`（v2/3）が対象です。他の言語やサブディレクトリの依存関係、実行環境への影響は調査しません。
- 公開版はブラウザからGitHubとOSVへ直接問い合わせます。GitHubの認証情報は使いません。OSVへ送るのは、公開lockfileから取り出した依存名と版です。
- 調査時間は最大45秒が目安です。照合は最大400パッケージ版までで、上限・API制限・取得失敗を画面に表示します。
- 公開版の履歴は、そのブラウザに最新20件・合計2 MiBまで保存します。端末間では同期しません。ブラウザのデータを消す前に、必要な結果をダウンロードしてください。
- ローカル版の履歴は `.data/` に保存します。調査結果を、判断や修正を記録する案件へ引き継ぐこともできます。

詳しくは[OSS採用前調査の仕様](docs/repository-research.md)を参照してください。

![このリポジトリの公開情報を調査した画面](docs/images/repository-research.png)

</details>

## 開発・運用する人向け

### テストを実行する

| コマンド                                     | 確認する内容                                 |
| -------------------------------------------- | -------------------------------------------- |
| `npm run check`                              | 型検査・単体/APIテスト・ビルド               |
| `npm run test:e2e`                           | ローカル版のブラウザ操作                     |
| `npm run build:pages` → `npm run test:pages` | 公開版のビルドとブラウザ操作                 |
| `npm run test:quality`                       | 単体/API・ブラウザテストをまとめたカバレッジ |

ブラウザテストの前に、一度 `npx playwright install chromium` を実行してください。ローカル版のブラウザテストには、ビルド済みのアプリが必要です。

<details>
<summary>カバレッジの基準と結果の保存先</summary>

`npm run test:quality` は、次の基準を下回ると失敗します。

- 全体：行・文・関数・分岐がそれぞれ90%以上。
- ファイルごと：行90%以上、分岐85%以上。
- 変更行：90%以上。

変更行の比較には過去のコミットを使います。shallow cloneの場合は、先に `git fetch --unshallow` を実行してください。

結果は `.cache/coverage-combined/` に保存します。`index.html` でレポート、`gate.json` で合否を確認できます。`lcov.info` と、実行対象のハッシュを含む `run-identity.json` も出力します。JUnit形式の結果は `.cache/quality/` に保存します。

ローカル版のテスト用ビルドは `.cache/coverage-build` を使います。テスト用サーバーのポートは、ローカル版が4318、公開版が4319です。通常の製品ビルドに計測処理は含めません。

CIでも同じカバレッジ基準と、通常ビルドでのブラウザテストを確認し、レポートを保存します。

</details>

<details>
<summary>資料管理・AIモデル・任意ツールとの連携</summary>

**資料管理**

ローカル版では、プロジェクト作成と左側の一覧から、資料の取り込み・手動比較・要件レビューを使えます。「サンプルで試す」は、まだレビューしていない手動比較の例を作る機能です。

既存プロジェクトから、個別のCVEをOSV・CISA KEV・FIRST EPSSで調べることもできます。

**AIモデル**

初期状態では、質問と回答を手動で受け渡します。ローカルモデルや外部モデルを使う場合は、[接続設定](docs/continuous-research.md#モデル接続)と、案件ごとの許可が必要です。自動で別のモデルへ切り替えることはありません。

**memx-resolver**

資料の同期・検索・参照・鮮度確認を行う任意連携です。ローカルで専用ストアを起動し、本アプリの起動時に `MEMX_URL=http://127.0.0.1:7766` を設定します。未接続でも基本機能は使えます。

**agent-protocols**

通常の `npm ci` で固定版を導入し、出力操作のときだけ読み込みます。アダプターなしで動かす場合は、通常の手順でビルドしてから次を実行します。

```sh
npm ci --omit=dev --omit=optional --ignore-scripts
npm start
```

アダプターがなくても、基本機能と内部タスク契約の出力は使えます。開発ビルドには、通常の `npm ci` を使ってください。

</details>

<details>
<summary>旧版から更新する</summary>

更新前にアプリを停止し、`.data/` をバックアップしてください。

旧データベース（`user_version=1`）は、起動時に版2へ移行します。原文と過去のスナップショットは保持します。旧版の出典参照は、未検証の根拠・主張（Evidence / Claim）として取り込みます。旧版で承認した内容は、再レビューが必要です。

旧版のアプリでは、更新後のデータベースを開けません。

</details>

## このアプリに含まれないもの

- 攻撃や脆弱性の再現。
- 任意コマンドの実行や、修正作業の自動実行。
- 診断サーバーのホスティングと、複数ユーザーの認証。

TaskSeedは作業案として出力します。実際の作業は、利用者の既存ワークフローで行います。
